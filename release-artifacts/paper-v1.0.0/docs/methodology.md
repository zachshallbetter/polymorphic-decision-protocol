# Methodology

## Design

This is a Type II protocol-specification analysis, not an empirical study. The method is structured inspection of the frozen normative protocol, mapping of proposed stages and assumptions, repository source/test inventory, and a bounded review of primary literature relevant to scoring, forecast combination, debate, and sycophancy.

## Sources and selection

The protocol source is the v1.3.0 text in the v1.3.2 repository baseline. The implementation source is the Rust and TypeScript code and associated tests in that baseline. External literature is selected for direct relevance and recorded in `sources/source-register.csv`. The search is preliminary rather than systematic; it cannot support an exhaustive novelty claim.

## Analysis

Claims are classified by evidence lane and maturity in `claims.jsonl`. The software matrix distinguishes design documentation, code presence, unit tests, and empirical validation. No quantitative analysis of model outputs or human decisions was performed. No outcome data were accessed.

## Validation and falsification

The present paper is subject to two independent human reviews. Future instrument testing requires blinded coding and reliability assessment. Future efficacy evaluation requires prospective registration, a defined population and outcome horizon, baseline comparator, prespecified estimand, uncertainty reporting, and complete outcome handling. The relevant failure conditions are recorded in the paper and stress register.
